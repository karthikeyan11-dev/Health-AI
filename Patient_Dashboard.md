One architectural rule I strongly recommend

Don't make every page independently fetch everything.

For example, Overview can fetch a dashboard summary endpoint, while detailed pages fetch their own paginated/history data:

GET /patients/me/overview

GET /patients/me/sensor-readings
GET /patients/me/cardiovascular-assessments
GET /patients/me/stress-assessments
GET /patients/me/digital-twin
GET /patients/me/emotions
GET /patients/me/recommendations
GET /patients/me/chat-sessions
GET /patients/me/chat-sessions/{sessionId}/messages
GET /patients/me/reports

These are logical API responsibilities, not a claim that all these exact endpoints already exist. The final paths/operationIds should be derived from your existing OpenAPI conventions before implementation.

This gives the patient side a clean end-to-end story:

Monitor → Assess → Understand → Get AI Support → Receive Recommendations → Download Reports.
